**Решения и отклонения от плана**
- **Astro 7 вместо 6.** Сначала был закреплён Astro 6.4.8 по плану, но `npm audit` показал в Astro ≤ 7.2.7 критические уязвимости (XSS, RCE при оптимизации AVIF), исправленные только в 7.x. По решению владельца проект переведён на Astro 7.3.5; в требованиях, `tech-stack.md` и `CLAUDE.md` заменён только номер версии. Текст `implementation-plan.md` (упоминания «Astro 6» в шагах 1.1, 1.3, 3.2) по правилам не менялся — читать его как «Astro 7». После перехода `npm audit` — 0 уязвимостей.
- **TypeScript 6.0.3, не 7.x.** `@astrojs/check` 0.9.10 поддерживает только TypeScript `^5 || ^6`.
- **Удалены `site/AGENTS.md` и `site/CLAUDE.md`** (симлинк), созданные мастером: в них советы про React/Tailwind, противоречащие стеку, и они перекрывали бы корневой `CLAUDE.md`.
- `npm ls` помечает `@img/sharp-wasm32` как extraneous — это необязательный запасной бинарник `sharp` из lockfile, на работу не влияет.

**Важно для следующих этапов (Astro 7)**
- Markdown в Astro 7 обрабатывает **Sätteri**, а не remark/rehype. `markdown.rehypePlugins` без пакета `@astrojs/markdown-remark` не работают. Плагин подписей (`src/lib/rehype-figure.mjs`, шаг 6.5) нужно писать как **HAST-плагин Sätteri**: объект `{ name, element(node, ctx) { ... ctx.replaceNode(...) } }` — дерево то же, что в rehype (hast), импорты не нужны. Подключение: `markdown: { processor: satteri({ hastPlugins: [figure] }) }`, где `satteri` — из `@astrojs/markdown-satteri` (зависимость самого `astro`). Пользовательские HAST-плагины выполняются до встроенного плагина картинок Astro, поэтому `<img>` нужно оставлять нетронутым, только оборачивать.
- `compressHTML` по умолчанию теперь `'jsx'` — пробелы между инлайн-элементами в `.astro` вырезаются как в JSX; учитывать при вёрстке (например, «компания · год»).
- Компилятор на Rust требует закрывающих тегов у всех не-void элементов.

**Как проверить**
```bash

npm ci
npx astro check     # 0 errors, 0 warnings
npm run build       # без предупреждений
npm run dev         # http://localhost:4321 — стартовая страница, /cv.pdf — CV
```

**Сделано**

- `index.astro` — `Hero` + `CaseList`; временный список удалён.

**Решения**
- **Кликабельность всей карточки** — «растянутая ссылка»: ссылка в заголовке + `.link::after { position:absolute; inset:0 }` на `position:relative` карточке. Нет вложенных ссылок, Tab проходит по карточкам по одной, экранный диктор читает ссылку названием кейса. «Посмотреть кейс →» — декоративный `<span aria-hidden>`.
- Фокус с клавиатуры рисуется на `::after` — обводится вся карточка, а не только заголовок.
- Визуал в DOM идёт после текста (правильный порядок чтения), а на <1024px поднимается наверх через `order: -1`.
- Строка мета собирается шаблонной строкой `` `${company} · ${year}` `` — из-за `compressHTML: 'jsx'` пробелы между отдельными выражениями могли бы потеряться.
- `value` — `white-space: nowrap` («до −30%», «300+ млн ₽» не рвутся); `label` ограничен `15em` по ширине.
- Цвета ховера/тени — через `color-mix()` от токенов, новых HEX нет.

**Решения и отклонения**
- **Плагин подписей без собственной рекурсии.** В Sätteri обход дерева делает движок (`element: { filter: ['p'], visit }`), а менять дерево можно только через `ctx.replaceNode` — ручная рекурсия по `node.children` изменений не применит. Пункт требований «обход дерева рекурсией» выполнен средствами движка.
- Плагин стоит до встроенного `image-marker` Astro, поэтому новый `<img>` внутри `<figure>` всё равно оптимизируется (проверено: WebP, 153 → 54 КБ). `title` с картинки снимается — он уже в подписи, всплывающая подсказка была бы дублем.
- `satteri` импортируется из `@astrojs/markdown-satteri` — прямая зависимость `astro`, отдельно не устанавливается (как в документации Astro 7). При обновлении Astro проверять, что импорт жив.
- Верхняя панель — `<header>` вне `<main>` через именованный слот `Base` (`slot="header"`); отдельный компонент не заводился — панель есть только на странице кейса.
- Ширины тела: каждый прямой потомок `.prose` — `max-width: var(--text-max)` по центру; `<figure>` и `<p>` с картинкой — `var(--media-max)`.
- Обложка в шапке не обрезается (естественные пропорции) — макеты обычно нельзя кадрировать; в карточке на главной — 16/10 с `object-fit: cover`.
- После изменения `astro.config.mjs` dev-сервер перезапускается сам.

## Этап 8. SEO и Яндекс Метрика — 05.10.2026

**Сделано**
- `Base.astro` — `og:type` (`website`), `og:locale`, `og:site_name`, `og:title`, `og:description`; при заданном `SITE_URL` — `og:url` и `og:image` (абсолютные). Картинка OG — `getImage()` → JPEG 1200px из `ogImage` (главная — `site.photo`, кейс — `cover`).
- `Base.astro` — Яндекс Метрика: официальный код (`is:inline` + `define:vars`), `<noscript>`-пиксель; только при `site.metrikaId`. Цель `goalOnLoad` отправляется сразу; один делегированный обработчик кликов шлёт цель из `data-goal`.
- `[slug].astro` — `goalOnLoad="case_open"`, `ogImage={cover}`; `index.astro` — `ogImage={site.photo}`.
- `astro.config.mjs` — `site` из `SITE_URL` (окружение или `site/.env` через `process.loadEnvFile`), `@astrojs/sitemap` только при заданном `SITE_URL`.
- `public/robots.txt` — `User-agent: *` / `Allow: /`, без `Sitemap` (нет домена).

**Решения**
- **`.env` читается штатным `process.loadEnvFile()` Node** (22+), без пакетов. Переменная из окружения важнее `.env`.
- `og:image` выводится только с `SITE_URL` — соцсетям нужен абсолютный адрес. Формат JPEG (не WebP) — его понимают все соцсети и мессенджеры. Исходник меньше 1200px не увеличивается.
- `og:type` везде `website` — интерфейс `Base` из плана не меняли ради `article`.
- Sitemap сам исключает `404`.
- Вебвизор в коде Метрики не включён (`clickmap`, `trackLinks`, `accurateTrackBounce`). Включить — добавить `webvisor: true` в `ym(…, 'init', {…})`.

## Этап 9. Анимации, доступность, работа без JavaScript — 05.10.2026

**Сделано**
- `CaseList.astro` — появление карточек при прокрутке: каждая карточка обёрнута в `<div class="item" data-reveal>`; инлайн-скрипт с `IntersectionObserver` ставит `js-reveal` на `<html>` и добавляет `is-visible` обёрткам, попавшим в окно (opacity 0→1, `translate` 1.5rem→0, 600ms).
- `ImagePlaceholder.astro` — `aria-hidden="true"`: заглушки декоративные, подпись дублирует компанию из соседнего текста.
- `public/favicon.ico` — иконка «АР» (16/32/48 px, PNG внутри ICO).

**Решения**
- **Без JS ничего не скрыто:** скрытое состояние описано только под `html.js-reveal`, а этот класс ставит сам скрипт. Нет `IntersectionObserver` или включён `prefers-reduced-motion` — скрипт выходит, карточки видны сразу.
- Анимируется обёртка, а не `.card`: у карточки свой `transform` для ховера; анимация через отдельное свойство `translate` на обёртке не конфликтует с ним.
- Контраст (WCAG): текст/фон 17.3:1, второстепенный/фон 6.3:1, второстепенный/подложка 5.7:1, акцент/фон 6.4:1, белый/акцент 6.7:1 — всё ≥ 4.5:1.
- **`favicon.ico` возвращён.** PDF-просмотрщик браузера (вкладка с CV) не видит `<link rel="icon">` и запрашивает `/favicon.ico`; без файла браузер показывал закэшированный логотип Astro. ICO собран без пакетов: `qlmanage -t -s 256` рендерит `favicon.svg` в PNG, `sips -z` — размеры 16/32/48, короткий Python-скрипт упаковывает PNG в ICO. **При смене иконки пересобрать оба файла** (`favicon.svg` и `favicon.ico`) и поднять `?v=` в `Base.astro`.

**Как проверить**
```bash
cd site && npm run dev
# прокрутка главной — плавное появление; DevTools → Rendering → prefers-reduced-motion: reduce — карточки сразу;
# Disable JavaScript — всё видно; Tab: CV → LinkedIn → Telegram → карточки → футер; /cv.pdf в инкогнито — иконка «АР»
```
